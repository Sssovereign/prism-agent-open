# 研究模式

本页维护当前辩论与独立陪审的行为。首版随 `0.0.2-beta` 交付，工程取舍见 D68，证据见首版验收。运行版本与后续验证见工程状态。

## 使用与阶段

顶部工作模式选择“辩论分析”或“独立评审”，选择任务模型，可分别指定角色模型，粘贴共同资料后提交。辩论默认2轮，可选1—3轮：正反独立初稿→每轮正、反各一次→主持汇总。初稿和交锋次数分别计数。独立陪审为三份初判→一次聚合；已完成辩论可点“由陪审团独立复核”。角色使用独立Pi会话，首版按阶段顺序运行，不宣称并行提速。

初稿和三位陪审初判各自提前冻结同批输入，全部提交后发布。初判复核已有辩论时拿到相同原始资料和双方发言，隐藏主持报告与彼此初判；聚合才引入主持报告及锁定意见。使用同一模型不消除共同偏差，独立上下文也不证明独立知识来源。

公开文字补充在下一个未冻结阶段生效；已冻结的独立批次保持相同基线，不因完成先后分配不同补充。最终汇总视图冻结后拒绝新补充，须新建研究。提前汇总保留初稿屏障、完成当前发言、跳过未开始交锋，然后主持收尾，结果标为`early_summary`；主持阶段已开始后拒绝提前汇总，完整辩论不会被误标为提前结束。取消则停止执行，不产生成功报告。

## 执行身份与输入范围

`ResearchCoordinator`管理状态，复用`runs/phase_tasks/attempts`、真实Pi runner、模型网关、持久凭据和用量登记。新增迁移019，不修改旧迁移；`research_participants`保存每位参与者独立模型快照，历史四角色`agent_bindings`只承担兼容外键，不能用其普通角色替代真实参与者身份。

票据绑定参与者、阶段和视图；模型请求开始事件记录这些标识。固定视图包含记录ID、内容SHA256、补充基线及工具清单。初始提示不继承普通对话、checkpoint、产物、AGENTS.md、用户附加提示、技能、MCP或子代理。项目规则、技能清单、附加工作目录与显式附件同属ordinaryTools能力束，仅普通工具快照run装载；固定`research-v1`的run在升级后仍维持这份受限视图，不随主会话配置漂移。每个阶段新建独立会话；压缩和跨视图恢复入口被关闭。目录和正文按可用空间装载，片段明确标记，保存原文不改写；模型网关仍对实际请求实施上下文预算检查。累计原文的旧600000字节门槛已取消，见下方按需读取说明。

正反及陪审员可用 `research_read`、`research_search` 和 `web_fetch`。角色的模型接口启用搜索或账号配置了全局搜索服务时，工具清单也下发 `web_search`。主持和聚合只可读取／搜索授权研究记录。工具在 Pi 清单和可信后端两处核验。`research_search`只匹配当前视图及本阶段自行抓取的原文，不返回隐藏记录的存在性。网页原文按本阶段保存，重试仍可通过授权工具查回本阶段已抓取资料；初始固定输入基线不会因此改写。公开事件和用户可见私稿均不会自动进入其他参与者的输入。

这约束应用提供给模型的信息与工具，不提供对宿主恶意进程的文件隔离。普通Agent的D53本机文件能力保持原有行为。

## 新研究任务卡与提示词版本

| 版本 | 内容 | 适用范围 |
| --- | --- | --- |
| 旧研究装配 | 原角色提示、固定研究视图与兼容 `methods` 冻结正文 | 历史 run、显式 `research-v1` 回归 run、仍使用旧 `methods` 正文注入的新 run |
| `research-task-card-v1` | 精简稳定规则、角色/阶段任务卡、必答 ID、限量记录摘要、简短 JSON 契约 | 新建且使用普通 Agent 只读能力、未走旧 `methods` 正文入口的研究 run |

研究创建时冻结 `promptVersion`；retry 和后续 phase 沿用同一版，旧任务不因升级而换提示。任务卡只列当前角色职责、当前可见的已发布主张、异议/评审/决策要求和允许输出字段。已公开发言以摘要和少量主张线索进入首轮上下文；需要论据全文或逐项初判详情时用 `research_read` 按需读取，避免把完整历史文本反复塞进每一阶段。

新任务复用普通 Agent 的只读项目工具和 Skill manifest，正文按需读取。项目规则、附加目录、Skill manifest 由 runner 分层注入，不在研究记录目录中重复全文。普通文件/图片读取结果目前不会自动成为结构化 research source，因此只能作为分析输入；不得伪造 `sourceId` 或逐字 `quote`。结构化 evidence 仍只能引用当前视图中已保存的 source 原文。图片可用于正文观察，但暂无区域级图片引证格式。记忆索引若启用，只作为有限背景导航，不是证据或授权。文件内容与 Skill 正文均视为数据，不得改变工具权限；读取能力不授予共享写入、Shell、记忆写入或产物发布权限。

格式校验失败时，新任务只收到长度受限的错误说明和短修复要求，不重复整个任务卡和资料目录。服务端同时记录脱敏的结构化拒绝诊断：类别、字段路径、期望值和修正提示；不记录原始模型输出或资料正文。诊断通过控制通道传入修复轮，最多两次；耗尽后以`DELIVERY_INVALID`终结当前阶段，保留已完成阶段、拒绝事件和冻结视图，用户可原地重试未完成阶段。结构校验、引文校验、预算/阶段状态和失败恢复均由服务端控制。

## 证据、主张与报告

共同资料保存不可变正文；网页读取保存正文、最终URL、摘要及截断标记。搜索仅返回链接／摘要，不能直接当原文证据。引证必须引用当前可见source记录，连续逐字匹配已保存正文。系统验证“有原文”和“引文匹配”，不自动认定资料可信或引文足以支持主张。`verify_source`重抓原网址后按空白归一的全量正文比对：原记录完整正文仍逐字出现在重抓内容中判matched，任何位置改动判changed——不能被“开头一致”的页面绕过。

每条主张使用阶段命名空间，回应只能引用可见的已发布主张且不得重复。主持须逐项记录已有主张接受、驳回、部分接受或未解决及理由。资料、主张与引证关联写入既有resources/resource_versions、arguments、argument_responses、evidence和argument_evidence；陪审逐项评审的引证同样入证据表（locator携带criterionId，不与主张关联）并计入报告证据统计；原文正文由research_records保存。

阶段结果、发布、状态与对应控制事件在同一SQLite事务中提交；重复相同完成回报幂等，内容变化冲突，过期attempt和取消后回报不能发布。无效输出不发布；最多两次格式修复，仍未通过则失败。拒绝理由与截断后的候选输出仅供属主审计，不作为其他角色输入。失败重试保留已提交阶段及原视图，重启后也从持久状态恢复，阶段间中断不重复已完成初判。

规范报告只保存一份`research_runs.report_json`，界面与JSON下载读取同一对象。流程完成／提前汇总、原文引证状态、程序统计、模型文字分别展示。无引证可以完成流程，但明确标记证据不足。v1陪审分类为支持／反对／部分成立／资料不足／弃权，人数从三份锁定初判计算；v2票型集来自冻结配置，程序计票口径见决策协议一节。模型不能覆盖票数。文字分析仍可能有错误，不能用模型文字中的票数代替程序记录。

整场上限按发起时的设置冻结：默认240次模型请求、480次工具请求、累计模型与工具执行90分钟（可在40—400／60—600内调整；旧版run沿用其发起时刻冻结的次数与45分钟时长，不随版本漂移）。ordinaryTools 阶段的按需读取让每次工具回合计入模型请求，预算消耗显著高于旧协议，上限相应放大。失败重试与格式修复都计入次数，用户等待恢复的闲置时间不计入执行时间。并非按货币计费上限，实际用量沿模型网关记录。

研究输入按参与者冻结的模型窗口装配，不再以累计保存资料超过600KB直接拒绝阶段启动。提示词先提供观点／评审意见及资料目录，正文按可用输入空间有限装载；未装载的原文仍完整保存在当前视野中，可用 `research_read(recordId,offset,limit)` 按需逐段核对（UTF-16位置从0开始，默认2000、最多8000字符）。`research_search` 返回匹配附近的有限原文片段，`query="*"` 配合 offset／limit 分页列出目录；网页抓取只向模型先返回前8000字符，剩余正文可通过 sourceId 分段读取。片段返回标记 contentTruncated／nextOffset，hash始终对应保存的完整原文，源网页自身截断仍单独保留。视图可见性、封存初判、完整原文逐字引证检查及模型网关的真实上下文预算仍生效，不能将按需装载解释为无限模型窗口。

因旧600KB门槛失败的汇总可在升级后点击“重试未完成阶段”，保留三份已提交初判及冻结视图。议题／共同资料输入框的20000字符限制与此运行时问题分开，本次未调整。

## 决策协议（research-v2）

完成报告以主持建议或独立评审的多数判定开头。有条件通过时显示关键待达成条件。决定性依据直接展开对应主张和引证，阻断项展开对应评审标准、陪审员判定与引证。报告末尾提供复核、结论异议、续聊和执行入口。完成态按需展开普通输入区，主张异议在对应主张旁填写。

新研究默认使用`research-v2`协议；升级前创建的run由`research_runs.policy_version`钉在v1语义，重试与新阶段仍按原协议执行。辩论可选「决策模式」：冻结命题与2—6个候选（含「维持现状」），主持汇总必须给出`disposition`（采用/试验/暂缓）及硬约束、范围、成功条件、复评触发点、缺失证据与取得方式、重新裁决条件，并引用决定性主张——缺失或空数组的`basisClaimIds`按交付格式错误拒绝。独立评审冻结被评对象（标题+中性原文）与1—12条评审标准（可标必达）：陪审员逐项给出满足/未满足/证据不足，全部必达标椎判「满足」才可投「通过」；「有条件通过」须列明待达成条件。多数陪审员判定未满足或证据不足的必达标准，汇总必须提供对应阻断项（阻断项条数上限与标准条数同界，逐条绑定标准ID且同一标准只收一条；多数陪审员判定「满足」的标准不能标为阻断——阻断项与陪审员判定在报告中同屏展开，不得相反）；多数判定为「不通过」却无此类标准时（含全部标准都是非必达），至少提供阻断项或下一步建议。票型集为通过/有条件通过/不通过/证据不足/弃权（弃权须写明理由），票数由程序从锁定初判计算，「通过」与「有条件通过」分别计票，多数=同一判定至少两票；复核继承的历史初判只供汇总视图阅读，不参与本轮计票。主持与汇总必须提供非空摘要。冻结的决策、候选ID、被评对象与标准随快照进入`config_snapshot_json`，阶段切换后保持。

## 用户异议与复核

异议目标是具体主张（`{type:'claim',claimId}`，claimId=阶段任务ID:主张key，须指向来源研究已发布主张）或整份结论（须已成功出报告）。运行中经steer带目标提交，落为`objection`类研究记录；同一clientMessageId换文本或换目标返回`IDEMPOTENCY_CONFLICT`。v2主持与汇总必须对视野内全部用户异议逐条回应（accepted/rejected/partial/unresolved+理由），遗漏、重复或越权ID由parse拒绝；回应与回应人角色随报告`objections`组装。一次最多携带8条、每条1—2000字符（运行中steer带目标的异议与终态复核入口同限，超限按`VALIDATION_FAILED`拒绝）；上下文预算内异议优先装载，装不下时降级为仅元数据且始终保留。初判阶段的视野排除主持、意见、判定与异议记录（初判隔离）。复核创建支持辩论或评审来源（同用户同项目同议题），已停止研究的终态异议随创建请求进入新run；复核继承的历史异议（带来源出处）保留查阅、不进必答清单。陪审初判字段不因objection记录存在而解锁——异议回应只出现在主持/汇总输出。

## 同会话续聊与执行交接

研究会话允许创建普通run（沿用账号、项目、授权与活动run互斥）：研究活动时普通创建与研究重试统一返回`CONVERSATION_BUSY`，研究停止后同会话创建成功、原重试入口保留。`contracts/conversation.ts`每个run带`mode`；会话窗口独立于分页返回研究锚点（会话内最近一次研究run的ID、模式、状态与议题），侧栏或刷新后据此重建研究面板。普通run创建时冻结预算受控（≤4000字符）的研究上下文（议题、最终摘要、关键决策、证据状态、限制、来源）进`config_snapshot_json`，runner以平台注入块呈现，完整正文仍在面板按需查阅；时间线只投影普通run。

执行交接：前端按报告生成可编辑草稿（目标/依据/范围/验收项），确认后走普通创建接口提交`researchHandoff:{sourceRunId,items}`；后端校验来源归属（本人、已成功出报告的研究）与验收项（1—20条、每条1—2000字符），把来源研究与验收项冻结进普通run快照，验收项同时注入任务正文。runner被要求在最终回复末尾输出「【助手回报】」小节，逐项回报「已通过/未通过/待人工确认」及产物、检查输出或原因；前端将最终消息中的回报小节结构化为带状态标签的清单（v0为呈现层约定，程序级独立核验另行评估）。会话查找同时命中研究记录（authorType=research并携带phaseTaskId），定位到研究面板`data-phase-id`锚点。

在续聊中恢复的研究报告也可发起复核，使用面板所展示的来源研究。复核表单取候选方案、主张或既有被评对象原文作草稿；旧裁决和异议交由汇总视图阅读，不参与本轮计票。运行中异议遇到提交失败时保留草稿，相同内容重试复用同一提交标识。

## 接口与界面

- `POST /api/v1/projects/:projectId/research`：mode、objective、rounds、models、可选sources、sourceRunId（辩论或评审来源）、decision（辩论决策模式：命题+候选）、subject与criteria（评审被评对象与标准）、objections（终态异议随复核创建）、attachmentIds（显式图片附件：创建时冻结元数据；任一角色模型不支持图片输入则创建阶段整体拒绝并点名角色，不启动任何阶段）；每位角色单独指定模型。
- `GET /api/v1/runs/:runId/research`：阶段（phaseKey/roundNo/模型展示名/工具活动/拒绝回报；拒绝回报含脱敏诊断、字段路径和修复进度）、视图、记录、失败和拒绝回报、规范报告（含objections与逐条回应、v2处置/决策/逐项标准/程序计票）。
- `POST /api/v1/runs/:runId/research/summarize`：辩论提前汇总。
- `GET /api/v1/runs/:runId/research/export`：下载同一研究投影，含规范报告。
- `POST /api/v1/runs/:runId/steer`：普通补充之外支持`target`（运行中异议带目标提交）；同一clientMessageId不同内容或目标冲突。
- `POST /api/v1/projects/:projectId/runs`：研究会话内创建普通run，可选`researchHandoff:{sourceRunId,items}`。
- `GET /api/v1/runs/:runId/conversation`：窗口runs带`mode`，另返回独立于分页的研究锚点`research`。
- `GET /api/v1/runs/:runId/find`：命中扩展到研究记录（authorType=research，携带phaseTaskId）。
- 原有cancel/retry/resume接口分派至研究流程；研究不支持重新回答锁定结果、通用压缩和图片补充。归档删除清理新增表，独立陪审已复制的记录不会因原辩论删除而丢失。

全部接口复用本机Host／Origin、登录、写请求CSRF及项目属主校验。研究页面展示阶段、封存状态、原文引证和上下文基线，可下载完整记录。这里吸收dsh-context逐层展开的呈现思路，未安装或移植原插件完整功能；没有逐组成Token估算、完整Fleet面板或跨会话内容浏览器。

网页读取无需搜索 Key。关键词搜索的服务选择、模型接口绑定与凭据解析见搜索服务扩展。

## 验证边界

控制协议正确、模型实际遵守格式和研究结论有用是不同问题。受控集成使用真实Pi／网关／本机HTTPS合成上游；实际DeepSeek使用独立账号、合成共同资料和既有测试凭据，未读取正式项目资料。单案例通过不能证明优于同预算单Agent，也不代表完整实地调查、Windows产品链或多供应商验收。详见版本回执。
